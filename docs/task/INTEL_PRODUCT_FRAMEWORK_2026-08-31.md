## 0. 核心定位（一句话介绍）

**把电竞直播弹幕，变成可溯源、可支持决策的情报，并且越攒越值钱。**

**我们做什么**：多路直播间（虎牙 / SOOP / KICK）的弹幕，按比赛节点加工成
结构化情报——赛前共识、BP 后、局中、局末、赛后复盘；事实层用官方数据
（Riot / Liquipedia / HLTV / Polymarket 结算）校准，弹幕只负责提供"观众
怎么看、有什么信号"。

**给用户带来的价值**：

- 决策者（付费）：赛前 BP 到局中，1-2 分钟拿到别人刷几个小时弹幕也整理不出的
  东西——灰信号、BP 锚点、观众共识、盘口讨论，每条可溯源、可验证；
- 普通观众（免费）：赛后复盘 + 验证闭环（当时怎么说、后来准不准）+ 知识摘要，
  看懂比赛、看懂共识；
- 长期资产：选手 / 队伍 / 英雄 / 联赛四个维度的知识越攒越厚，形成复利情报库——
  这是别人零散经验、我们系统性积累的差异化。

## A. 产品框架

### A1. 定位

以弹幕情报为内核（A），输出成综合情报台形态（B）；B 的内容全部来源于 A，
官方数据只做校准与溯源，不喧宾夺主。

一句话：**多路直播弹幕 → 可溯源、可支持决策的电竞情报**。

### A2. 目标用户与付费场景

- 付费用户 = 预测市场 / 博彩决策者；决策窗口集中在赛前 BP 到局中。
- 普通观众 = 免费漏斗（赛后复盘 + 验证闭环），再往订阅转化。

### A3. 差异化支柱

1. 信息差：灰信号、BP 锚点、观众共识、多语言弹幕归并——别人整理不出来的东西；
2. 可验证：预测 / 灰信号 / BP 锚点的验证痕迹，单条可溯源。

### A4. 覆盖范围

聚焦 LoL（LCK / LPL / LEC）+ CS2 主流赛事，做深不做宽；
Dota2 / Valorant 只预留不投入。

### A5. 免费 / 付费边界

- 免费：赛后复盘（比赛一结束，该场所有节点页自动转公开）、验证闭环、
  四维知识摘要（选手 / 队伍 / 英雄 / 联赛）；
- Pro：进行中的节点情报（BP / 局中 / 局末）、完整知识资产；
- Pro 墙只挂两处：进行中的节点页 + 完整知识资产，其余全公开。

### A6. 定价

单一全量订阅（LoL + CS2 全包）：$59/月、早鸟 $39/月，维持现状不变。

### A7. 覆盖承诺

覆盖当天所有已登记联赛场次；缺数据显式标「无 / 此节点暂未采集数据」，不硬凑；
资源不足时按有盘口 / 热门场次优先；每场至少赛后复盘兜底。

### A8. 时效 SLA（北京时间）

- BP 后快报 ≤ 2 分钟；
- 局中快报 ≤ 2 分钟；
- 完整版 ≤ 10 分钟；
- 赛后复盘 ≤ 15 分钟。

触发机制：节点触发不靠固定时间轮询，用事件驱动（官方状态变化：BP 锁定 / 开局 /
小局结束 + 弹幕密度峰值）。每节点记录「触发 → 快报 → 完整版 → 上线」四段时间戳，
SLA 变成可回归的指标。

### A9. 页面结构

维持现有导航结构，只做微调；验证闭环与画像库提升为一级入口；
今日页每场比赛必须展示节点进度（未开始 / 进行中 / 已结束 + 已出节点）。

### A10. 信息源与多语言

- 虎牙主源 + SOOP LCK CL（韩文中文化，原文折叠）；
- Twitch 暂停，不自动启用；KICK 用于 CS2；
- 时间一律北京时间展示。

### A11. 沿用 / 不展开项

- 验证闭环指标口径（预测命中率 / 灰信号兑现率 / BP 锚点应验率）：按现状执行，不设新决策；
- 试用 / 续费策略（1 美元 3 天试用、TG 登记）：按现状执行，不设新决策。

### A12. 情报库与知识资产（复利资产）

定位：不是自动合并弹幕统计，而是把每场比赛中**有价值的情报**提炼成长期知识，
按 选手 / 队伍 / 英雄（地图）/ 联赛 四个维度持续积累。统计只是底料，
沉淀的是情报本身及其证据与验证。

- 每场沉淀：本场情报资产（主题 / 维度 / 洞察 / 证据 / 置信 / 验证状态 / 时间）；
- 四维知识：
  - 选手：英雄池与招牌英雄、风格标签、状态趋势、名场面、BP 锚点、灰信号记录；
  - 队伍：战术体系与版本适应、BP 倾向、翻盘 / 顺风能力、状态趋势、跨场战绩；
  - 英雄 / 地图：强度认知、counter 关系、出场 / 胜率趋势、观众共识黑话；
  - 联赛：晋级规则、节奏、版本环境、强队格局、盘口习惯；
- 幂等合并 + 趋势线延伸 + 验证回填（灰信号兑现率 / BP 锚点应验率 /
  预测命中率持续累加）；
- 摘要免费，完整知识资产 Pro；所有引用带时间与来源。

## B. 弹幕加工引擎（核心）

### B1. 四步流水线

```text
采集（多路直播间弹幕流，纯程序）
  → 规则统计底料（词表 / 提及量 / 密度 / 灰信号计数 / 时间窗切片，纯程序）
  → LLM 自由提炼（固定提示词 + 底料 + 该时间窗代表弹幕样本；群体共识用自由段落描述；
     主动保留规则统计覆盖不到的特殊情报，不过度过滤）
  → 校验门禁（结构完整 / 官方校准 / 反讽识别 / 无中生有拦截 / 时间戳核验）
```

不设独立「意见归并 / 聚类层」（2026-08-26 聚类方案曾失败回滚；避免层层加工
把有价值信息过滤掉、拖慢效率）。规则统计只做轻量底料，判断与叙事交给 LLM 一步完成。

### B2. 时间窗纪律（硬要求）

每个节点的弹幕只使用**本节点对应比赛时段**的数据：

- 切片起点 = 本节点阶段起点（如 G3 BP 节点从 G3 选人 / 开局开始，不含 G2 结束后的局间）；
- 用官方 schedule / 弹幕密度突变校准确认阶段边界；
- 禁止混入上一局尾段、局间闲聊、更早节点、他场他联赛数据；
- 整场复盘必须全窗口等距抽样，不只喂尾部（2026-08-31 教训：full 时间线偏移）。

### B3. 价值单元

情报由两类内容构成，缺一不可：

1. 持续观点：队伍 / 选手 / BP / 盘口共识（整场累计，带提及量与占比）；
2. 事件反应：一血、团战、偷家等关键节点时弹幕爆发（带时间戳与强度，
   往往是灰信号与翻盘信号最密集处）。

### B4. 可信度字段（每条情报必带）

来源分层（本场弹幕 / 前局延续 / 历史画像 / 盘口）+ 置信（多源确认 / 单源待验证 /
弹幕口径·待官方）+ 样本量 + 时间窗（北京时间）。

### B5. 词表维护

半自动：LLM 定期从新弹幕发现候选词 → 规则 + 人工确认入表 → 回归测试防漏。
禁止全自动（玩梗 / 谐音如 OKBRO、bro tax 会误收成信号）。

### B6. 弹幕情报红线

1. 无中生有零容忍：只有简单推断、无本场 / 前局 / 历史数据支撑的不写；
2. 事实层只信官方（Riot window / Liquipedia-HLTV / Polymarket 结算），弹幕禁止单独定胜负；
3. 反讽先判定：英文 / 玩梗弹幕无法判定时降级「未确认」；
4. 灰信号永远标「观众质疑 · 非结论」，禁作假赛证据；
5. 跨场选手 / 队伍话题标注「跨场话题 · 不适用本场」，禁入本场画像与锚点；
6. 时间线只用真实弹幕时间戳，禁止编造 / 换算 / 平移；
7. 方向表达只罗列证据（正锚 / 负锚 / 群体共识），不下「看好 X」类结论。

## C. 情报输出模板（旧 10 段框架回归）

### C1. 唯一标准

`knowledge/INTEL_TEMPLATE_OLD_2026-08-31.md` 为当前唯一模板标准
（zip：intel_server_pkg_2026-08-31_oldframework.zip）；
样页：`reports/template_samples/intel_danmu_LCKCL-NS-DNSC_full_old_2026-08-31.html`（+ MD 镜像）。

### C2. A 型整场复盘（0-10，缺一不可）

```text
0  比赛信息（赛事 / 队伍 / 时间 / 赛制 / slug）
1  结果总览（弹幕口径 · 官方待回填 → 官方结算后回填）
2  逐局复盘（BP / 时间线 / 转折点 · 每局一段，含阵容）
3  队伍画像（本场弹幕口径 + 引用 teams.json）
4  人员画像（带提及量 · 引用 players.json）
5  灰信号汇总（观众质疑 · 非结论 · 前置风险标注）
6  联赛规律与版本（可统计项）
7  预测验证（弹幕共识 vs 结果 · 闭环回填）
8  盘口讨论（Polymarket 结算价交叉 · 让分 / 大小 / 独赢）
9  情报含义与后续观察点（LONG / SHORT）
10 数据与溯源（实际 / 预期 / 缺口 + 源明细）
```

### C3. B 型局中快照（A 骨架局中版，0-11）

```text
0  比赛信息
1  结果总览 / 状态核验（弹幕口径 · 未结束；结束判定四类信号逐项核对）
2  弹幕规模、密度峰值与事件时间线
3  阵容与 BP / 英雄讨论（官方 window 校准；BP 后战绩情报必抓）
4  队伍画像（本窗口 + 跨场沉淀）
5  人员画像（带提及量）
6  灰信号汇总（观众质疑 · 非结论）
7  方向性情报（锚点 × 群体共识 × 灰信号）
8  联赛规律与版本
9  预测验证（框架 · 赛后回填）
10 盘口讨论（样本不足则标注）
11 情报含义与后续观察点（LONG / SHORT）
```

### C4. 赛前（PRE）版

0 比赛信息 → 1 赛前共识与状态核验（弹幕口径 · 未开赛）→ 2 队伍画像（本窗口 + 历史库）→
3 人员画像（带提及量）→ 4 灰信号汇总 → 5 联赛规律与版本 → 6 盘口讨论（无则「待开赛」）→
7 情报含义与后续观察点（LONG / SHORT）→ 8 数据与溯源。

### C5. 节点与快报

- BP 后 + 局中：先出快报（1-2 分钟，规则直出硬统计：比分 / 提及量 / 灰信号数），
  页面标注「速览版 · 完整版跟进」，同 URL 原地升级为完整版；
- 局末：直接完整版；
- 完整版 = 上述模板结构 + 可溯源 + 门禁全过，才算正式交付。

### C6. 与 12 段框架的差异（切换要点）

1. 删掉「核心情报速览」速览卡硬性门槛：speedcard_consistency 不再作为发布门禁；
2. prompts/ 按 10 段骨架重写（去掉 0 速览卡 / 5 方向板 / 6 决策落点三段，回归 C2-C4 结构）；
3. 保留硬性规则不变：数据带量、灰信号纪律（观众质疑非结论）、结果标「弹幕口径」、
   BP 后战绩情报必抓、MD 镜像必出、match_state_guard 四道闸、来源分层、
   跨场选手标注「不适用本场」、时间线真实时间戳、缺口三栏显式标注；
4. 生成端门禁按「每段恰好出现一次」执行（缺段 / 重复段都判不过并重试）。

## D. 防错与保障（四类失效模式）

### D1. 情报混淆（LoL 混进 CS、不同场次混数据）

1. 切片硬隔离：每场切片只允许该场 + 该联赛默认采集集；跨联赛混源整场作废，不局部修补；
2. 生成门禁：跨联赛 / 跨场词表扫描（CS 页出现 LoL 队名选手名、本场页出现他场队名 → 判不过）；
3. 发布审计：页面 × 联赛 × 关联 slug 交叉校验，关联不上不上线；
4. 旧污染页必须被正确替换（文件名 / 路径 / 大小写校验），G5 真页面禁止被发布清理误删
   （修复：以 runtime/vps_intel 的 g5 状态文件为保留依据，不依赖 matches.json 文字比分）。

### D2. 时效滞后

1. A8 SLA 硬承诺；
2. 事件驱动触发（官方状态 + 弹幕密度峰值），不靠轮询；
3. 四段时间戳可观测（触发 → 快报 → 完整版 → 上线）；
4. 部署链路压缩：快报同 URL 直接上站，不等整场生成完。

### D3. 价值下降

1. 四步引擎 + LLM 自由提炼 + 保留特殊情报，不过度过滤；
2. 价值单元双类（持续观点 + 事件反应），都带量、带时间戳；
3. 合格标准回归「发生了什么 + 意味着什么 + 可溯源」；
4. 禁止把章节标题、元数据碎片、纯时间线当情报。

### D4. 格式混乱

1. 唯一模板权威（C 部分旧 10 段框架），快报也走固定模板，不允许自由发挥；
2. 节点命名统一（BP / 局中 / 局末 / 整场固定后缀固定字段）；
3. 门禁「每段恰好一次」；
4. 发布前全站格式审计，不通过不发布。
