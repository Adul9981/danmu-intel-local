一句话定位

把电竞直播弹幕，变成可溯源、可支持决策的情报，并且越攒越值钱。

多路直播间弹幕（虎牙为主）→ 按比赛×节点切片 → 规则统计（词表/提及量/密度/灰信号） → LLM 提炼（固定提示词）→ 门禁校验 → HTML+MD 情报输出 → 结构化情报库沉淀 → 验证回填

事实层（时间/队伍/比分/选手×英雄·地图/结算）一律以官方源校准（Riot / Liquipedia / HLTV / Polymarket 结算），弹幕只提供"观众怎么看、有什么信号、有什么质疑"。

对你（接手云迁移）最有价值的部分

① 云端工程 PRD v2.0 —— 整个项目的"设计蓝图"：架构分层、12 个模块详设（输入/输出/验收）、数据设计、部署剧本、测试清单、里程碑 M0-M5、验收标准。先读它，再动代码。
② 部署手册 + deploy/ —— systemd 单元、采集服务、发布定时器、nginx 配置，按步执行即可在 VPS 跑起来。
③ 核心代码路径 —— 采集（run_danmu_session）→ 切片（slice_danmu_by_match）→ 统计（danmu_intel）→ 生成（generate_intel_report/danmu_report）→ 发布（vps_publish）。这条链路读通 = 项目读通。
④ 门禁与防错 —— match_state_guard 四道闸 + 终局四信号，是本项目质量的生命线（弹幕提前庆祝/预测 ≠ 终局，CS2 加时制参数化），迁移时务必保留并回归测试。
⑤ 模板与样例 —— 先看样页（LCKCL 整场、CS2 Aurora-G2 三加时/决胜局/整场），再对照模板，快速理解"一份合格情报长什么样"。
注意：原始弹幕大数据、密钥/Token、runtime 状态不在仓库内（隐私与体积考虑）；结构化情报库（docs/data/intel/）已包含脱敏统计。Twitch 明确不采集，虎牙为主源。

快速开始（本地验证）

# 1. 采集（多直播间同场会话） python3 tools/run_danmu_session.py --session <name> --room <source>=<url> ... # 2. 切片（比赛×节点时间窗） python3 tools/slice_danmu_by_match.py --manifest <manifest.json> # 3. 规则层统计 python3 tools/danmu_intel.py --input <slice.jsonl> --out intel.json # 4. 生成情报页（A 型整场 / B 型局中 / 赛前） python3 tools/danmu_report.py --input intel.json --template full

完整工作流见 knowledge/DANMU_WORKFLOW.md；云端版设计见 docs/task/DANMU_INTEL_CLOUD_PYTHON_PROJECT_PRD.md。
