## 一、页面使命（一句话）

用户进入页面 **5 秒内拿到"这场比赛什么情况、有什么关键信号、该关注什么"**，
辅助快速做交易决策；赛后能回填验证、能沉淀进队伍/选手画像库。

## 二、12 段结构与顺序（决策导向，缺一不可）

```text
0  核心情报速览（第一屏 · 硬性门槛 · BLUF）
1  比赛信息与结果总览 / 状态核验（比分/进度/MVP + 官方待回填 + 跨源一致性）
2  灰信号汇总（风险红线 · 前置 · 观众质疑非结论）
3  BP 锚点与选人情报（赛前强信号 · 前置；CS2=地图池/禁选）
4  盘口与市场讨论（机会信号 · 前置）
5  方向性情报板（正锚×负锚×共识×灰信号条件预测 · 一屏看方向）
6  情报含义与决策落点（LONG/SHORT + 本场观察点 · 前置）
7  逐局复盘（证据层 · 必带真实时间线）
8  队伍 / 人员画像（证据层 · 带提及量）
9  联赛规律与版本（沉淀层）
10 预测验证回填（沉淀层 · 闭环）
11 数据与溯源（沉淀层 · 实际/预期/缺口三栏）
```

层级逻辑：**决策层（0-6）回答"什么情况/有什么信号/该看什么"；
证据层（7-8）回答"为什么"；沉淀层（9-11）回答"可信度/可复用"**。

## 三、速览卡硬性格式（§0）

```text
1) 比分/进度一行（含「弹幕口径·官方待回填」标签）；
2) TOP 信号 3-5 条，按「风险→锚点→盘口→共识」顺序；
   每条 = 类型标签 + 一句话中文意译（含关键对象与方向）+
           价值句（So-What，≤35 字，含方向与置信标签：多源确认/单源待验证/
           弹幕口径·待官方）+ 溯源（→ 详 §N）；
3) 一句话决策落点（"本场建议关注 / 边际信息在…"）；
4) 灰信号条目必须带「观众质疑·非结论」；无信号写「今日无信号」。
```

门禁纪律（2026-08-31 事故教训）：
- 每条速览卡 = **单箭头结构**（信号 → 价值），禁止一条里堆多个"→"；
- 价值句必须含强词（看衰/利多/多源确认/单源待验证/弹幕口径·待官方等）；
- 禁止章节标题/元数据碎片/纯时间线/表格头；
- **跨场选手/队伍（NiKo/Falcons、donk/Spirit、Zywoo/VIT）严禁进入本场速览卡**，
  只可标注"跨场话题·不适用本场"。

## 四、加厚版密度标准（用户定稿，最高）

```text
1. 速览卡焦点制：≤5 焦点，每条=类型+事件+价值+溯源；
2. 证据层 <details> 折叠 ≥3 个（弹幕原文摘录 / 长画像 / 完整时间线）；
3. 逐局必带弹幕时间线：真实北京时间戳 + 原文带量；
4. 群体共识 ≥5 行（含分歧与样本量）；
5. 密度目标：整场 ≥16KB / 局中 ≥15KB；
6. 人员画像保留 选手/提及量/评价 三列，带正负向；
7. 整场复盘（full）必须覆盖全窗口样本（spread 抽样），禁止只看尾部。
```

## 五、事实层与来源分层（最高纪律）

```text
来源优先级（结果类）：
  Polymarket 结算 > 官方 API（Riot window / Liquipedia→HLTV）> 官方直播间标题
  > 中文战报 > 弹幕情绪（弹幕禁止单独定胜负）。
来源分层（结论类）：
  核心 = 本场弹幕；补充 = 前局弹幕/历史画像（必须标注来源与时间）；
  推测 = 仅基于已发生事件 + 标注「推测·待验证」；
  单源 = 待验证；多源共振 = 确认；方向背离 = 分歧（单独标注）。
硬规则：
  - 选手×英雄/阵容只信官方 window/HLTV，弹幕提及 ≠ 实际选人；
  - CS2 阵容待 HLTV 回填时写"待官方回填"，禁止编造；
  - 时间线时间戳必须原样使用样本时间，禁止换算/编造/平移；
  - 灰信号只作风险标注（观众质疑·非结论），不作假赛证据。
```

## 六、数据完整性三栏（§11 必有）

```text
实际数据源：本场采集到的源（如 SOOP afchall + 硕硕 + 毛毛）；
预期数据源：该联赛默认采集集（leagues.json）；
缺口：离线未采 / 断采时段 / 未回填项——显式标注，禁止静默跳过。
```

## 七、沉淀与闭环（§10 + 入库）

```text
1. 每页结尾给「本场长期沉淀点」≥1 条（可进 teams.json 队伍特质/选手画像）；
2. 比赛结算后自动回填：预测验证 / 灰信号兑现 / BP 锚点应验；
3. HTML + MD 镜像双份并存（knowledge/intel_pages/），登记索引；
4. 入库：matches / teams / players / gray_signals / bp_signals / leagues；
5. 可见性：库里有 → 页面必须有 → 索引必须有（禁止"库里有、页面没有"）。
```

## 八、生成与门禁流水线

```text
1. 切片：按比赛/节点时间窗精确切（同场同会话、跨联赛分会话）；
2. 规则层：danmu_intel.py 输出统计（总条数/提及量/密度/灰信号/特质）；
3. 生成：generate_intel_report.py + prompts/（固定提示词，全窗口抽样）；
4. 门禁：
   - speedcard_consistency.py --check（empty/noisy/no_value 任一即拦）；
   - match_state_guard.py（时间门槛/结构源优先/反讽识别/比分源滞后）；
   - 12 段齐全 + <details>≥3 + 无编造胜率；
5. 发布前自检：页面内跨场队名/选手名搜索（防张冠李戴）；
6. MD 镜像 + 索引 + 结构化库同步。
```
